# AutoTrainer — короткий технічний опис

## Ідея
Система будує цикл автоматичного донавчання комп’ютерного зору через **перехресну перевірку YOLO та ConvNeXt**:
- YOLO детектує бокси.
- ConvNeXt класифікує кропи (людина / галюцинація).
- Розбіжності між моделями використовуються для відбору інформативних прикладів.

Мета — мінімізувати ручну працю та стабільно покращувати якість моделей у продакшені.

---

## Компоненти
- **data_collector** — збір даних з камер, збереження фреймів і боксів у Blob, формування індексних CSV з метаданими.
- **deduplicator** — зменшення надлишковості даних через pHash + DSU (транзитивне об’єднання схожих зображень), формування `*_filtered.csv`.
- **labeler** — GUI для швидкої ручної розмітки та експорту датасетів для донавчання.

---

## Формат даних (CSV)
Один рядок = один bounding box.
Обов’язкові поля:
- `box_blob`, `frame_blob`
- `x1, y1, x2, y2`
- `yolo_score`, `cnext_sscore`
- `phash`
- `created_ts` (unix time)

`*_filtered.csv` містить підмножину рядків після дедуплікації.

---

## Дедуплікація
- Обчислюється **pHash** для кропів.
- Схожі зображення об’єднуються через **DSU** (з транзитивністю).
- З кожного кластера відбирається обмежена кількість прикладів з рівномірним покриттям у часі.
- Результат зберігається у `*_filtered.csv` без зміни структури колонок.

---

## Розмітка (labeler)
GUI дозволяє:
- переглядати **кроп + фрейм** одночасно;
- масштабувати та панорамувати зображення;
- вмикати/вимикати bbox на фреймі;
- розмічати одним кліком: **TP / FP / Skip**;
- працювати не по порядку (навігація);
- зберігати стан у SQLite та продовжувати з будь-якого місця;
- безпечно **перерозмічати** (relabel) з коректним видаленням старих експортів.

Використовується кеш і prefetch для швидкої роботи з Blob.

---

## Логіка експорту
### ConvNeXt
- **TP** → кроп у `train/TP` або `val/TP`
- **FP** → кроп у `train/FP` або `val/FP`
- Експорт залежить від `cnext_score` та `tolerance`.

### YOLO
- Зберігається **фрейм**, якщо бокс вказує на FN або FP YOLO.
- Ураховується `yolo_score`, поріг та `tolerance`.
- Один фрейм може мати кілька причин експорту (reference tracking).

---

## Train / Val split
- Виконується **по кількості кадрів**, у хронологічному порядку.
- Split фіксується при завантаженні камери.
- Skip не впливає на split.

---

## Результат
Після розмітки формується:
- датасет для **ConvNeXt** (кропи, TP/FP, train/val);
- датасет для **YOLO** (фрейми, по камерах, train/val);
- повністю відтворюваний процес донавчання.
